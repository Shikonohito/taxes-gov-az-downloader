# Как работает скрипт

## Назначение

Скрипт автоматизирует работу с разделом электронных счетов-фактур на портале
`https://new.e-taxes.gov.az/eportal`. Он открывает управляемый браузер, при
необходимости инициирует вход через Asan İmza, выбирает кабинет по VÖEN, переходит
к отправленным счетам-фактурам и сохраняет два Excel-отчёта:

- `Qaimələr üzrə` — отчёт по счетам-фактурам;
- `Ödəyicilər üzrə` — отчёт по плательщикам.

Скрипт автоматизирует пользовательский интерфейс портала с помощью Playwright.
Он не обращается к закрытым API портала напрямую и не пытается обходить Asan
İmza. Подтверждение кода и ввод PIN1 выполняются владельцем номера на телефоне.

## Состав проекта

- `src/index.mjs` — основной сценарий браузерной автоматизации;
- `src/config.mjs` — загрузка `.env`, нормализация и проверка настроек;
- `.env.example` — пример пользовательской конфигурации;
- `test/config.test.mjs` — проверки нормализации настроек;
- `test/automation.test.mjs` — браузерная проверка выбора кабинета, вкладки и
  обработки загрузки;
- `test/run.mjs` — точка запуска тестов;
- `downloads/` — каталог результатов и диагностических снимков;
- `.browser-profile/` — отдельный постоянный профиль Chromium.

Каталоги `downloads/`, `.browser-profile/`, `node_modules/`, локальный `.env` и
служебный `.agents/` исключены из Git.

## Общая последовательность

При выполнении `npm start` происходят следующие действия:

1. Загружается файл `.env`.
2. Проверяются и нормализуются настройки.
3. Создаются каталоги загрузок и профиля браузера, если их ещё нет.
4. Запускается Chromium с постоянным профилем.
5. Скрипт пытается сразу открыть `/eportal/invoice`.
6. Если портал перенаправил браузер на страницу входа, запускается вход через
   Asan İmza.
7. После подтверждения PIN1 выбирается кабинет с заданным VÖEN.
8. Открывается раздел счетов-фактур и вкладка `Göndərilənlər`.
9. Последовательно запрашиваются два Excel-отчёта.
10. Файлы сохраняются в `downloads/`, после чего браузер закрывается.

Если действующая сессия уже сохранена в `.browser-profile/`, этапы входа и
подтверждения на телефоне пропускаются.

## Загрузка конфигурации

В начале `main()` вызывается `loadEnvFile()`. Функция читает `.env` построчно и
поддерживает:

- пустые строки и строки-комментарии, начинающиеся с `#`;
- необязательный префикс `export`;
- значения в одинарных или двойных кавычках;
- комментарии после некавыченного значения.

Переменные, уже заданные в окружении процесса, имеют приоритет: `.env` их не
перезаписывает. Это позволяет при необходимости передавать настройки из CI,
PowerShell или другого менеджера секретов.

### Основные переменные

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `ASAN_PHONE` | Номер телефона после `+994` | отсутствует |
| `ASAN_USER_ID` | Шестизначный ID Asan İmza | отсутствует |
| `TAXPAYER_TIN` | VÖEN кабинета | ручной выбор кабинета |
| `DOWNLOAD_DIR` | Каталог итоговых файлов | `downloads` |
| `BROWSER_PROFILE_DIR` | Каталог постоянного профиля | `.browser-profile` |
| `BROWSER_CHANNEL` | Канал браузера Playwright | `chromium` |
| `AUTH_TIMEOUT_MS` | Ожидание PIN1 и кабинета | `300000` мс |
| `DOWNLOAD_TIMEOUT_MS` | Ожидание каждого отчёта | `180000` мс |
| `SLOW_MO_MS` | Задержка между действиями | `0` мс |

### Нормализация значений

`ASAN_PHONE` очищается от пробелов, скобок, дефисов и других нецифровых
символов. Если передан полный номер из 12 цифр, начинающийся с `994`, код страны
удаляется. После нормализации должны остаться ровно девять цифр.

`ASAN_USER_ID` также очищается от нецифровых символов. Результат должен состоять
ровно из шести цифр.

Из `TAXPAYER_TIN` удаляются пробелы. В оставшемся значении разрешены буквы,
цифры и дефисы. Пустое значение допустимо и включает ручной выбор кабинета.

Пути `DOWNLOAD_DIR` и `BROWSER_PROFILE_DIR` преобразуются в абсолютные пути
относительно рабочего каталога, из которого запущена команда.

## Запуск браузера и сохранение сессии

`launchContext()` вызывает `chromium.launchPersistentContext()`. В отличие от
одноразового контекста браузера, постоянный контекст хранит cookies и local
storage в `.browser-profile/`. Благодаря этому портал может сохранить
авторизованную сессию между запусками.

Основные параметры браузера:

- `headless: false` — браузер видим пользователю;
- `acceptDownloads: true` — Playwright принимает загрузки;
- `downloadsPath` — временная область загрузок связана с итоговым каталогом;
- `locale: "az-AZ"` — используется азербайджанская локаль;
- размер окна страницы — `1366 × 900`;
- `slowMo` берётся из `SLOW_MO_MS`.

Один каталог профиля нельзя одновременно использовать в двух процессах
Chromium. Поэтому две копии `npm start` с одинаковым
`BROWSER_PROFILE_DIR` запускать не следует.

## Определение необходимости входа

`ensureAuthenticated()` сначала открывает:

```text
https://new.e-taxes.gov.az/eportal/invoice
```

Это одновременно ускоряет повторный запуск и служит проверкой сессии. Если
портал не перенаправил браузер на URL с `/login` и форма
`#asan-sign-login-form` не отображается, сессия считается действующей.

Если требуется авторизация, браузер переходит на:

```text
https://new.e-taxes.gov.az/eportal/login/asan
```

Скрипт ждёт появления формы не более 30 секунд.

## Вход через Asan İmza

`fillAndSubmitAsan()` использует следующие элементы:

| Назначение | Селектор |
| --- | --- |
| Мобильный номер | `#phone` |
| ID пользователя | `#userId` |
| Кнопка входа | `#loginPageSignInButton` |

Если сохранённой сессии нет, но `ASAN_PHONE` или `ASAN_USER_ID` не заполнены,
скрипт завершает работу до отправки формы с понятным сообщением об ошибке.

После заполнения полей нажимается `Daxil ol`. В терминал выводится сообщение о
том, что запрос отправлен. Далее автоматизация не вводит PIN1 и не получает его:
пользователь сверяет код и подтверждает операцию на телефоне.

Максимальное время ожидания этого действия задаётся `AUTH_TIMEOUT_MS`. Значение
по умолчанию — пять минут.

## Выбор кабинета

После успешного подтверждения Asan İmza портал показывает доступные кабинеты.
За этот этап отвечает `waitForCabinetChoice()`.

Если задан `TAXPAYER_TIN`, скрипт каждые 250 мс проверяет два условия:

1. Уже появился элемент меню счетов-фактур — значит кабинет открыт.
2. На странице появился текст с нужным VÖEN — значит список кабинетов готов.

Поиск VÖEN допускает пробелы между символами. Например, конфигурация
`1234567890` совпадёт и с текстом `123 456 7890`.

Когда VÖEN найден, скрипт сначала ищет ближайший кликабельный родительский
элемент (`a`, `button` или элемент с `role="button"`). Если такого родителя нет,
нажатие выполняется по самому тексту: событие поднимается до обработчика карточки
кабинета.

Успешное открытие кабинета определяется по одному из вариантов селектора:

```text
[data-testid='menuInvoice'], #menuInvoice
```

Если `TAXPAYER_TIN` не задан, автоматизация просит пользователя выбрать кабинет
вручную и ждёт появления того же элемента меню.

## Открытие отправленных счетов-фактур

После авторизации `openInvoices()` убеждается, что браузер находится на
`/eportal/invoice`. Переход выполняется напрямую, поэтому нажатие бокового пункта
`E-qaimə-fakturalar` обычно не требуется.

Кнопка `Exceli endir` доступна не на всех вкладках. Функция
`ensureSentInvoicesSelected()` сначала проверяет, видна ли эта кнопка. Если нет,
она нажимает вкладку `Göndərilənlər` и ждёт появления кнопки экспорта.

Такой подход работает и при первом открытии раздела на вкладке `Gələnlər`, и
при повторном запуске, когда портал восстановил ранее выбранную вкладку.

## Запрос Excel-отчёта

В коде объявлены два вида экспорта:

```text
Qaimələr üzrə   → qaimeler-uzre
Ödəyicilər üzrə → odeyiciler-uzre
```

Для каждого вида `downloadExport()` выполняет один и тот же сценарий:

1. Ждёт видимую кнопку `Exceli endir`.
2. Нажимает кнопку и ждёт точный текст нужного пункта dropdown-меню.
3. Нажимает `Qaimələr üzrə` или `Ödəyicilər üzrə`.
4. Ждёт видимый диалог с сообщением:

   ```text
   Excel faylı yükləmək istədiyinizə əminsinizmi?
   ```

5. Находит видимый текст `Bəli` и нажимает его.
6. Ждёт браузерное событие `download`.
7. Сохраняет файл в настроенный каталог.

Кнопка `Bəli` ищется по всей странице, а не только внутри блока с сообщением.
Это сделано потому, что на реальном портале тело диалога и его футер могут быть
отрисованы соседними контейнерами.

Ожидание события загрузки регистрируется до нажатия `Bəli`:

```text
ожидание download + нажатие Bəli выполняются совместно
```

Так Playwright не пропускает быстро начавшуюся загрузку. Максимальное время
формирования одного отчёта задаётся `DOWNLOAD_TIMEOUT_MS` и по умолчанию равно
трём минутам.

Системный диалог «Сохранить как» не используется. Playwright принимает загрузку
и вызывает `download.saveAs()` с подготовленным абсолютным путём.

## Имена скачанных файлов

Имя формируется независимо от имени, предложенного сервером:

```text
YYYYMMDD-HHMMSS-<тип-отчёта>.xlsx
```

Примеры:

```text
20260827-152511-qaimeler-uzre.xlsx
20260827-152512-odeyiciler-uzre.xlsx
```

Если сервер предлагает расширение `.xls` или `.xlsx`, оно сохраняется. Любое
другое или отсутствующее расширение заменяется на `.xlsx`.

Если файл с таким именем уже существует, добавляется числовой суффикс:

```text
20260827-152511-qaimeler-uzre-2.xlsx
```

После `saveAs()` дополнительно проверяется `download.failure()`. Если Chromium
сообщает об ошибке загрузки, выполнение завершается с описанием причины.

## Последовательная обработка двух отчётов

Экспорты обрабатываются последовательно, а не параллельно. Сначала полностью
завершается `Qaimələr üzrə`, затем заново открывается меню и запускается
`Ödəyicilər üzrə`.

Это важно, потому что портал использует одно модальное окно и одно состояние
dropdown-меню. Параллельные нажатия могли бы закрыть меню, заменить выбранный вид
экспорта или связать событие загрузки не с тем отчётом.

## Завершение и обработка ошибок

Основной сценарий выполняется внутри `try/catch/finally`.

При успехе в терминал выводятся абсолютные пути обоих файлов. После этого
постоянный контекст закрывается, а cookies и local storage остаются в каталоге
профиля для следующего запуска.

При любой ошибке скрипт пытается сделать полноразмерный снимок текущей страницы:

```text
downloads/error-YYYYMMDD-HHMMSS.png
```

Затем в терминал выводятся сообщение ошибки и путь к снимку, а процесс получает
код завершения `1`.

Обработчики `SIGINT` и `SIGTERM` закрывают контекст при остановке через
`Ctrl+C` или при завершении процесса операционной системой.

## Безопасность данных

В репозиторий не должны попадать:

- `.env` с номером телефона, ID Asan İmza и VÖEN;
- `.browser-profile/` с cookies и состоянием сессии;
- `downloads/` с отчётами и диагностическими снимками.

Все эти пути перечислены в `.gitignore`. `.env.example` содержит только пустые
значения и может безопасно храниться в Git.

PIN1 отсутствует в конфигурации и исходном коде. Он вводится только на телефоне
через инфраструктуру Asan İmza.

Удаление `.browser-profile/` сбрасывает сохранённую браузерную сессию. После
этого при следующем запуске потребуется новый вход и подтверждение PIN1.

## Тестирование

Команда:

```powershell
npm test
```

запускает проверки конфигурации и локальный headless Chromium.

Тесты конфигурации проверяют:

- локальный и международный форматы номера;
- отклонение неполного номера;
- длину ID Asan İmza;
- удаление пробелов из VÖEN;
- преобразование относительных каталогов в абсолютные.

Браузерный тест создаёт локальную HTML-страницу без обращения к налоговому
порталу. На ней воспроизводятся:

- карточка кабинета и появление `menuInvoice` после выбора;
- отсутствие `Exceli endir` до нажатия `Göndərilənlər`;
- dropdown с видом отчёта;
- модальное окно, чей футер находится вне блока с сообщением;
- настоящее событие браузерной загрузки;
- сохранение полученного содержимого в `.xlsx`.

Тестовый каталог создаётся во временной директории операционной системы и
удаляется после проверки.

## Ограничения

- Скрипт зависит от текстов и структуры пользовательского интерфейса портала.
  При изменении подписей или DOM-селекторов автоматизацию потребуется обновить.
- Полностью автоматизировать PIN1 намеренно нельзя: подтверждение выполняется на
  телефоне владельца Asan İmza.
- Срок жизни авторизованной сессии определяет портал. Постоянный профиль не
  гарантирует бессрочный вход.
- Отчёты скачиваются для состояния и фильтров, активных в разделе
  `Göndərilənlər` на момент запуска.
- Одновременный запуск нескольких экземпляров с одним профилем не
  поддерживается.

## Диагностика типичных проблем

### Не запускается Chromium

Установите совместимую версию:

```powershell
npx playwright install chromium
```

и убедитесь, что в `.env` задано:

```dotenv
BROWSER_CHANNEL=chromium
```

### Код Asan İmza не приходит

Проверьте `ASAN_PHONE` и `ASAN_USER_ID`. Номер можно указать с `+994` или без
него: перед заполнением формы он нормализуется.

### Кабинет не найден

Проверьте `TAXPAYER_TIN` и увеличьте `AUTH_TIMEOUT_MS`, если список появляется
медленно. Можно временно оставить `TAXPAYER_TIN` пустым и выбрать кабинет
вручную.

### Кнопка `Exceli endir` не появилась

Скрипт автоматически выбирает `Göndərilənlər`. Если кнопки всё равно нет,
возможны изменение интерфейса, отсутствие необходимых прав или незавершённая
загрузка страницы. Смотрите последний снимок `downloads/error-*.png`.

### Формирование отчёта занимает слишком долго

Увеличьте `DOWNLOAD_TIMEOUT_MS`, например:

```dotenv
DOWNLOAD_TIMEOUT_MS=300000
```

Это значение задаётся отдельно для каждого из двух отчётов.
